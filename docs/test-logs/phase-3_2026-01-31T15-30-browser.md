## Issues Identified

### Issue 1: Confirmed box redirect not working

**Observed:** Navigating to `/box` after confirming shows "No box found for this week." instead of redirecting to `/confirm`.

**Cause:** `getCurrentBox()` only fetches boxes with `status: "draft"`. When box is confirmed, it returns `null`, so the redirect check `if (box.status === "confirmed")` never runs.

**Suggested Fix:** Check for confirmed box before checking for draft box, or modify `getCurrentBox` to return any non-delivered box.

### Issue 2: Confirmed boxes should remain editable until deadline

**Current behavior:** Once a box is confirmed, it cannot be edited (swap/remove disabled).

**Expected behavior:** Confirmed boxes should remain editable (allow swaps and removes) as long as the deadline has not passed (`hours > 0`). Only after the deadline passes should the box become truly locked.

**Rationale:** Users may want to make last-minute changes to their confirmed box. The confirmation is about intent to receive the box, not about locking the contents. The true lock should be time-based, not status-based.

**Suggested Fix:** 
1. Change draft box guards in `swapItem` and `removeItem` to allow both &apos;draft&apos; and &apos;confirmed&apos; statuses
2. UI should show swap/remove buttons for confirmed boxes when `hours > 0`
3. Locked mode (read-only) should trigger only when `hours <= 0`, regardless of status
